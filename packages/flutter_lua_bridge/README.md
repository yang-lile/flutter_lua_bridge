# flutter_lua_bridge

Run Lua in Flutter and Dart apps with synchronous calls in both directions.
Lua is compiled from source for the target platform by a build hook; nothing
needs to be installed. `LuaRuntime` is the single entry point, used directly
or through typed APIs generated by
[`flutter_lua_bridge_codegen`](https://pub.dev/packages/flutter_lua_bridge_codegen).

```sh
flutter pub add flutter_lua_bridge
```

```dart
import 'package:flutter_lua_bridge/flutter_lua_bridge.dart';

final lua = LuaRuntime.create(); // LuaLibrary.safe by default
try {
  lua['greet'] = lua.function((args) => 'hello ${args.first}');
  print(lua.eval('return greet("lua")')); // hello lua

  final config = lua.eval('return { size = 3, tags = { "a", "b" } }') as LuaTable;
  print(config.toDart()); // {size: 3, tags: [a, b]}
} on LuaBridgeException catch (e) {
  print('${e.message}\n${e.traceback}');
} finally {
  lua.close();
}
```

- **Values** cross the boundary as `null`, `bool`, `int`, `double`, `String`,
  `Uint8List`, or a handle (`LuaTable`, `LuaFunction`, `LuaThread`,
  `LuaUserdata`); Dart `Map` and `List` arguments are copied into new tables.
- **Errors** never crash the process: every operation runs protected, and a
  failure is a `LuaBridgeException` with `status`, `message` and `traceback`.
- **Sandboxing**: the default `LuaLibrary.safe` leaves out `io`, `os`, `debug`
  and native module loading; other `LuaLibrary` flags add them. Memory limits
  and interrupts are available on the runtime.
- **Threading**: calls are synchronous and confined to the isolate that
  created the runtime.

## Asynchronous Dart functions

A Dart function given to Lua may return a `Future`. Lua calls it as an
ordinary function and waits for the result without blocking the isolate,
when Dart runs that Lua code asynchronously:

```dart
lua['fetch'] = lua.function((args) async {
  await Future.delayed(const Duration(milliseconds: 10)); // a network call, say
  return 'body of ${args.single}';
});

final length = lua.eval('''
  return function(url)
    local body = fetch(url)          -- waits here; other Dart code keeps running
    return #body
  end''') as LuaFunction;

print(await length.callAsync(['/home'])); // [13]
```

A failed future raises a Lua error at the call. Lua code that Dart runs
synchronously (`call`, `eval`) cannot wait and gets an error explaining so.
With generated contracts, declare the method as returning a `Future`; see
[Asynchronous methods](https://github.com/yang-lile/flutter_lua_bridge/blob/main/docs/codegen-guide.md#asynchronous-methods).
Lua coroutines remain available as `LuaThread`s (`function.coroutine()`,
`resume`, `resumeAsync`).

## Typed contracts

Describe the API in Dart and let the generator write both sides:

```dart
@LuaApi(module: 'battle')
abstract class BattleApi {
  int calculateDamage(Fighter attacker, Fighter defender);
}
```

This library re-exports the annotations, so a contract imports only
`package:flutter_lua_bridge/flutter_lua_bridge.dart`. See
[`flutter_lua_bridge_codegen`](https://pub.dev/packages/flutter_lua_bridge_codegen)
and the step-by-step
[Getting started](https://github.com/yang-lile/flutter_lua_bridge/blob/main/docs/getting-started.md).

## Lua from a server

The Lua source is plain text loaded at runtime, so it can be delivered
without an app release. It must implement the contract the app was built
with, as source text (bytecode is rejected) within the sandbox you open.
See [Loading Lua at runtime](https://github.com/yang-lile/flutter_lua_bridge/blob/main/docs/dynamic-lua.md).

## Lua version

Lua 5.3, 5.4 (default) and 5.5 are bundled. Pick one in the workspace root
`pubspec.yaml`:

```yaml
hooks:
  user_defines:
    flutter_lua_bridge:
      lua_version: "5.5"
```

A local source tree or a downloaded archive works too; see
[Choosing the Lua source](https://github.com/yang-lile/flutter_lua_bridge/blob/main/docs/lua-source.md).
