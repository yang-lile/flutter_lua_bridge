# flutter_lua_bridge

A Dart contract describes an API; Lua or Teal implements `@LuaApi`
interfaces, Dart implements `@DartApi` interfaces, and `build_runner`
generates everything in between. Calls are synchronous in both directions and
confined to the isolate that created the `LuaRuntime`. Lua is compiled from
source by a build hook; no Lua, LuaRocks or Teal install is needed.

## Ownership: never edit generated files

| You write | Generated by `build_runner` (never edit) |
| --- | --- |
| `lib/bridge/<name>.dart` – the contract, with `part '<name>.g.dart';` | `lib/bridge/<name>.g.dart` – `XxxClient`, `registerXxx`, codecs, embedded Lua glue |
| `lua/src/*.tl` or `*.lua` – implementations of `@LuaApi` interfaces | `lua/types/<name>_bridge.d.tl` – Teal types of `require("<name>_bridge")` |
| Dart classes implementing `@DartApi` interfaces, and the app code | `assets/lua/*.lua` – compiled Teal / copied Lua, the only Lua shipped |
| `lua/test/main.tl`, `*_test.tl` – Lua-side tests | |

`build.yaml` and `tlconfig.lua` are written once by `init` and are then the
project's own. Files starting with `Generated by flutter_lua_bridge` or
`Do not edit` are output: change the contract or `lua/src` and regenerate.
There is no `<name>_bridge.lua` file; that module lives inside `<name>.g.dart`.

## Setup

```yaml
# pubspec.yaml
dependencies:
  flutter_lua_bridge: ^0.2.0
dev_dependencies:
  build_runner: ^2.17.1
  flutter_lua_bridge_codegen: ^0.2.0
flutter:
  assets:
    - assets/lua/
```

```sh
dart run flutter_lua_bridge_codegen:init     # directories, build.yaml, tlconfig.lua, lua/test/main.tl
dart run build_runner build                  # after every contract or lua/src change (or: watch)
```

The packages need Dart 3.14 (Flutter 3.50) or later. In a Flutter
project use `flutter pub add` / `dart run` the same way. `init` prints the
steps it could not do (assets entry, missing dependencies, an existing
`build.yaml` without `lua/**`).

## Writing the contract

```dart
import 'package:flutter_lua_bridge/flutter_lua_bridge.dart'; // re-exports the annotations

part 'battle.g.dart';

enum Element { fire, water }               // Lua sees strings: "fire", "water"

class Fighter {                            // a data class: your own class
  const Fighter({required this.name, required this.attack, required this.element});
  final String name;
  final int attack;
  final Element? element;                  // nullable: may be nil in Lua
}

@LuaApi(module: 'battle')                  // implemented in Lua, called from Dart
abstract class BattleApi {
  int damage(Fighter attacker, Fighter defender);
}

@DartApi(module: 'host')                   // implemented in Dart, called from Lua
abstract class HostApi {
  void log(String message);
}
```

Rules the builder enforces (violations fail the build and point at the
declaration):

- Types: `bool`, `int`, `double`, `String`, simple enums, data classes,
  `List<T>`, `Map<String, T>`, nullable forms of these, and `void` returns.
  Rejected: `dynamic`, `Object`, `Future`, `Stream`, function types,
  untyped collections, non-`String` map keys, and nullable elements
  (`List<int?>`, `Map<String, int?>`).
- Data classes: one unnamed constructor whose parameters are all required
  (positional, or `required` named, nullable ones too) and each initialise a
  `final` field of the same name; no other fields, no `extends`, no
  recursion. Enums must be simple (no members).
- Names must not clash with `Object` members (`hashCode`, `toString`, ...).
- Interfaces: abstract methods only; no getters, generic methods, optional
  parameters or concrete members. Required named parameters are allowed and
  become positional in Lua, in declaration order.
- An API may `implements` a plain abstract interface (no annotation) to share
  methods between APIs, typically to bind the same functions at several
  safety levels; `extends` and mixins are rejected.
- `@LuaName('lua_name')` renames a method, field or enum value on the Lua
  side. Without it the Lua name is the Dart name.

## Implementing a @LuaApi in Teal

`module: 'battle'` is the Lua module name; by convention the source is
`lua/src/battle.tl`, compiled to `assets/lua/battle.lua`.

```lua
local bridge = require("battle_bridge")    -- types from lua/types/battle_bridge.d.tl
local host = bridge.getHostApi()           -- the @DartApi implementation

local implementation: bridge.BattleApi = {
  damage = function(attacker: bridge.Fighter, defender: bridge.Fighter): integer
    host.log(attacker.name .. " attacks")
    return math.max(0, attacker.attack - defender.attack)
  end,
}
return bridge.bindBattleApi(implementation)
```

- The module must return `bridge.bindXxx(table)`. Binding wraps the table's
  functions in place, so one table binds one API; binding it as another API
  fails with "already bound as ...". Use a fresh table per binding.
- Teal types: `int` → `integer`, `double` → `number`, `List<T>` → `{T}`,
  `Map<String, T>` → `{string: T}`, data classes → `bridge.<Class>` records,
  enums → `bridge.<Enum>` string enums.
- Plain `.lua` works the same way without type checking.
- A shared helper module (`require("formulas")`) is not loaded
  automatically in the app: load it first with `runtime.loadModule`.

## Calling from Dart

```dart
final lua = LuaRuntime.create();                 // LuaLibrary.safe: no io/os/debug
try {
  registerHostApi(MyHost(), runtime: lua);       // before loading Lua that uses it
  // lua.loadModule('formulas', source: ...);    // helper modules required by battle
  final battle = BattleApiClient.load(
    runtime: lua,
    source: await rootBundle.loadString('assets/lua/battle.lua'),
  );
  switch (battle.damage(a, b)) {                 // O1/O2: LuaCallResult<int>
    case LuaSuccess(:final value):
      print(value);
    case LuaFailure(:final kind, :final message): // kind: type, runtime, protocol
      print('$kind: $message');
  }
} finally {
  lua.close();
}
```

`BattleApiClient(runtime: lua)` binds a module that is already loaded;
`registerHostApi(null, runtime: lua)` unregisters. Errors never crash the
process: native and loading failures throw `LuaBridgeException` (`status`,
`message`, `traceback`).

## Safety levels

| Level | Lua type checks | `pcall` | Dart result |
| --- | --- | --- | --- |
| `O1` (default) | yes | yes | `LuaCallResult<T>` |
| `O2` | no | yes | `LuaCallResult<T>` |
| `O3` | no | no | `T`; throws `LuaBridgeException`; the client `implements` the contract |

Set the project default with `optimization: O1|O2|O3` in the builder options
of `build.yaml`, or per interface with
`@LuaApi(module: 'battle', optimization: LuaOptimization.o3)`. Use O1 for
scripts that can change at runtime, O3 for trusted hot paths.

## Lua delivered at runtime

The Lua source is text passed to `XxxClient.load(source: ...)`, so it may
come from a server. The contract and the `<name>_bridge` glue are compiled
into the app, so a delivered script replaces only the implementation:

- Deliver the `assets/lua/<module>.lua` that `build_runner` writes from the
  same contract version as the installed app; source text only, bytecode is
  rejected. Version contracts yourself (a constant raised on every change).
- It must `return bridge.bindXxx(t)` with every contract method (a missing
  one fails at load; extras are ignored), use only the opened libraries,
  and `require` only modules loaded first with `runtime.loadModule`.
- Type mismatches surface per call (`LuaFailure`, `kind: type`), so keep
  `O1`, load into a new `LuaRuntime`, make one test call, then swap and
  `close()` the old runtime; fall back to the bundled asset on failure.
  Verify a signature before loading.

Details: `docs/dynamic-lua.md`.

## Testing the Lua side without the app

```sh
dart run flutter_lua_bridge_codegen:run                   # every main.tl / *_test.tl under lua/test
dart run flutter_lua_bridge_codegen:run lua/test/x_test.tl
dart run flutter_lua_bridge_codegen:run --watch
```

An entry passes when it returns without error; use `assert`. Teal is type
checked as in the build. Outside the app `bindXxx(t)` returns `t`, and
`getXxx()` returns an empty table that the test fills with stand-ins:

```lua
local bridge = require("battle_bridge")
bridge.getHostApi().log = function(_: string) end
local battle = require("battle")
assert(battle.damage({ name = "a", attack = 5 }, { name = "b", attack = 2 }) == 3)
```

From Dart tests: `await LuaRunner().run('lua/test/x_test.tl')` from
`package:flutter_lua_bridge_codegen/lua_runner.dart`.

## Widgets from Lua (flutter_lua_bridge_ui)

`flutter pub add flutter_lua_bridge_ui`. `LuaView(runtime:, source:)` runs a
chunk that returns `App {...}` and shows its widgets. Widgets, value types
and `App` are globals written like Flutter, with braces; `ui` holds the
helpers. The package depends on `package:flutter/widgets.dart` only.

```lua
local Item = ui.component(function(props)       -- setup: once per instance
  local s = ui.state { open = false }            -- local reactive state
  return function(props)                         -- render
    return GestureDetector {
      onTap = function() s.open = not s.open end,
      child = Padding {
        padding = EdgeInsets.all(8),
        child = Text { props.item.title, style = TextStyle { fontSize = 16 } },
      },
    }
  end
end)
return App {
  store = { items = { { title = "a" } } },       -- mirrored to LuaStore
  methods = { add = function(store, t) table.insert(store.items, { title = t }) end },
  view = function(store, props)
    return ListView.builder {
      itemCount = #store.items,
      itemBuilder = function(context, index)       -- zero-based, context is nil
        return Item { key = index, item = store.items[index + 1] }
      end,
    }
  end,
}
```

- Flutter names: arguments as in Flutter; array entries are only Flutter
  positional parameters (`Text { "hi" }`, `Icon { Icons.add }`); children
  are `child =` / `children = {}` (`Column { a, b }` is an error). Named
  constructors are fields (`ListView.builder`, `Image.network`). Values:
  `EdgeInsets.symmetric { horizontal = 8 }`, `BorderRadius.circular(8)`,
  `Color(0xFF2196F3)`, `MainAxisAlignment.center`, `FontWeight.w600`;
  `CrossAxisAlignment["end"]` because `end` is a keyword.
- Callbacks get Flutter's parameters (`onChanged = function(value)`).
  Arguments named `*builder`/`*Builder` are builders: Flutter calls them
  lazily and each output is its own component instance.
- A component renders again only when reactive state it read (`ui.state`,
  the store) changed or its props differ field by field; split lists and
  expensive parts into components, and prefer `ListView`/`ListView.builder`
  over a `Column` of many items. Use `ui.pairs`/`ipairs`/`#` on proxies.
- Material: `flutter_lua_bridge_ui_material`, `libraries: [coreLibrary(icons:
  ...), materialLibrary()]`, then `Scaffold {...}`, `ElevatedButton {...}`,
  `Colors.red.shade100`, `TextField { text = store.draft, onChanged = ... }`.
  Cupertino: `flutter_lua_bridge_ui_cupertino`, `cupertinoLibrary()`,
  `CupertinoButton {...}`, `CupertinoColors.systemBlue`.
- App widgets: `LuaWidgetLibrary(name:, widgets: {'X': (context, args) =>
  ...}, luaModules: {'app.widgets': 'return require("flb.ui").library("app",
  {"X"})'}, luaGlobals: 'app.widgets')`. Builders read `args.v<T>(path)`,
  `args.child`, `args.childList`, `args.voidHandler`, `args.handler(key,
  (trigger) => (v) => trigger([v]))`, `args.indexedBuilder`, and
  `LuaDecoders` for colors, insets, styles and enums.
- Dart functions for Lua: `LuaWidgetLibrary(functions: {'Api.load':
  (context, args) => ...})` plus a Lua module `return
  require("flb.ui").functions("app", {"Api.load"})` as `luaGlobals`; Lua
  calls `Api.load(x)`. `context` is the calling view's. A `Future` result
  makes the event handler or method wait (`local data = Api.load(x)`
  reads like `await`). The core library has `Navigator.pushNamed(name, {
  arguments = ... })` (returns the route's result), `pushReplacementNamed`,
  `pop(result)`, `maybePop`, `canPop` without the BuildContext; give every
  route its own `LuaRuntime` and pass `settings.arguments` as props.
- Host side: `LuaViewController.call(name, args)` runs a method;
  `LuaStore.get/set/watch` read and write the store (zero-based list
  indices in Dart paths). `props:` reaches `view(store, props)`.
- Teal: add `lua/types` and `lua` of each widget package to `include_dir`
  and start with `local ui = require("flb.ui.prelude")` (or
  `flb.ui.material.prelude`); arguments, enums and callbacks are checked.
  Type the store with a record: `view = function(s: Store, p: ui.Props): ui.Node`.

## Lua bundles (flutter_lua_bridge_remote)

Serve a directory of modules with a `bundle.json` written by `dart run
flutter_lua_bridge_remote:pack <dir> --name x --version 1.0.0 [--library
material]`, and show it with `RemoteLuaView(loader: LuaBundleLoader(source:
HttpBundleSource(uri), cacheDirectory: dir, fallback:
AssetBundleSource('assets/x/')), libraries: [...])`. Modules are checked
against their SHA-256 and cached per version; a version whose first render
fails is marked bad and the view falls back to the last good version, then
the built-in one. SHA-256 is not a signature: use HTTPS and `verify`.

## Raw runtime

For untyped use: `lua.eval('return 1 + 1')`, `lua.run(source)`,
`lua['name'] = value`, `lua.function((args) => ...)`, `LuaTable.toDart()`.
Values are `null`, `bool`, `int`, `double`, `String` or handles
(`LuaTable`, `LuaFunction`, ...); a Dart `Uint8List` becomes a Lua string and
Dart `Map`/`List` are copied into tables. Prefer the generated APIs for
anything with a stable shape.

`LuaWorker.spawn(setup: topLevelFn)` runs a runtime on a background isolate:
`await worker.call('mod.fn', [args], timeout: ...)`, `run`,
`interrupt()`, `close()`. Plain data only crosses; a timeout fails the call
with `LuaStatus.interrupted`. Use it for heavy or untrusted Lua.

## Troubleshooting

- `require("x_bridge")` reported missing in the editor: `tlconfig.lua` must
  be in the folder the editor opened (the package root), with
  `include_dir` covering `lua/src` and `lua/types`.
- Nothing generated for `lua/`: `build.yaml` must list `lua/**` under
  `targets.$default.sources` (`init` writes it).
- Asset not found at runtime: list `assets/lua/` under `flutter: assets:`.
- Lua version: 5.4 by default; set `hooks: user_defines: flutter_lua_bridge:
  lua_version: "5.3" | "5.5"` in the workspace root `pubspec.yaml`.
